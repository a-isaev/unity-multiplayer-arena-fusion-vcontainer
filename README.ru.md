# Coin Rush

[English](README.md)

Coin Rush — сетевая арена с видом сверху на 2–4 игроков. По замыслу за две минуты нужно собрать больше монет, чем соперники. Рывок позволяет оттолкнуть другого игрока.

Сейчас в проекте есть стартовая сцена, лобби Photon Fusion, тестовая арена с сетевым движением и раундами на сбор монет. Рывок и отталкивание работают через сетевую симуляцию Fusion.

## Подготовка проекта

1. Открой проект в Unity **6000.6.9f1**. Дождись импорта ассетов и установки зависимостей.
2. Если папки `Assets/Photon` нет, скачай [Photon Fusion 2 SDK](https://doc.photonengine.com/fusion/v2/getting-started/sdk-download) и импортируй пакет через **Assets → Import Package → Custom Package**.
3. В [Photon Dashboard](https://dashboard.photonengine.com) создай приложение типа **Multiplayer Game** с SDK **Fusion 2**. Скопируй его **App ID**.
4. В Unity открой **CoinRush → Photon Settings**, вставь App ID и нажми **Update App ID**. Unity создаст или обновит локальный конфиг. Git игнорирует этот файл.

## Проверка входа по коду

1. При первом открытии проекта Unity откроет сцену [Bootstrap](Assets/_Project/Scenes/Bootstrap.unity). Нажми **Play** в этой сцене. Стартовый экран загрузит материал арены из локальной группы Addressables, затем откроет меню.
2. В первом экземпляре игры нажми **Create room**, затем **Copy code**. Оставь этот экземпляр запущенным.
3. Запусти второй экземпляр, например отдельную настольную сборку из того же проекта. В поле **Room code** вставь код и нажми **Join room**.
4. При успешном подключении оба экземпляра покажут **Players: 2/4** при стандартном лимите игроков. Кнопка **Leave room** выводит из комнаты.

Если вход не удался, проверь, что хост ещё в комнате, код скопирован целиком, а App ID и регион совпадают. Причина сбоя отображается в лобби.

## Проверка сетевого движения

1. Пересобери настольное приложение из текущей версии проекта. Сборки с одним лобби используют другую версию приложения в Photon.
2. Создай комнату в Unity и подключись из обновлённой сборки. Арена открывается сразу после подключения.
3. Щёлкни по окну хоста и подвигай своего голубого персонажа с помощью **WASD** или стрелок. В окне клиента этот персонаж должен двигаться и отображаться оранжевым.
4. Щёлкни по окну клиента и повтори проверку в обратную сторону. На каждом экране голубым отмечен свой персонаж.

## Проверка раунда

1. Запусти два экземпляра текущей версии игры и подключи их к одной комнате.
2. Когда все участники подключатся, нажми **Start round** в окне хоста. Монеты появятся на полу, а счёт и таймер — в левом нижнем углу.
3. Подойди к монете. Она исчезнет в обоих окнах, и счёт подобравшего игрока увеличится. Когда собраны все монеты, на арене появится новая партия.
4. По истечении времени оба окна покажут победителя или ничью. Хост может нажать **Play again**, чтобы начать новый раунд. Пока идёт раунд, войти могут только отключившиеся участники этого раунда.

## Проверка рывка

- Нажми **Пробел** с направлением движения. Если стоишь на месте, персонаж рванёт в сторону последнего движения, а при первом рывке — вверх.
- Наведи рывок на соперника. Хост применит одно отталкивание к первому игроку на пути, и оба окна покажут его смещение.
- Повтори нажатие до окончания кулдауна в **1,5 секунды**. Новый рывок начнётся только после восстановления и нового нажатия. Остаток времени виден в панели комнаты.

## Сенсорное управление на Android

После входа в комнату удерживай палец на **Move** слева и тяни в нужную сторону. Отпусти палец, чтобы остановиться. Нажми **Dash** справа для рывка. Можно удерживать стик одним пальцем и нажимать рывок другим. Кулдаун отображается в панели комнаты.

## Тесты правил раунда

В Unity открой **Window → General → Test Runner**, выбери **EditMode** и запусти `CoinRush.Tests.RoundTests`. Тесты проверяют таймер, подбор монет, победу, ничью и повторный раунд. Для запуска не требуется подключение к Photon.

## Оформление арены

Монеты светятся, а персонаж вспыхивает на время рывка. HDR-цвет задаёт Shader Graph `ArenaGlow`, а на desktop Bloom применяется камерой арены через URP. На Android Bloom и HDR отключены. Материал пола, игроков и монет входит в локальную группу Addressables и собирается вместе с приложением.

## WebGL

Браузерная версия предусмотрена как экспериментальный клиент. Создай комнату на macOS или Android и введи её код в браузере. Создание комнаты доступно в нативных сборках. У этого режима Fusion есть ограничения по стабильности и производительности. [Документация Photon](https://doc.photonengine.com/fusion/v2/fusion-choose)

## Возврат в текущий раунд

1. Начни раунд, набери очко на клиенте и нажми **Leave room**, оставив окно клиента открытым.
2. Попробуй подключиться из отдельного экземпляра игры. Хост должен отклонить вход, пока раунд идёт.
3. В исходном окне клиента войди по тому же коду. Игрок вернётся в прежнюю строку счёта и сможет продолжить собирать монеты. Таймер идёт и во время отключения.
4. После завершения раунда новые игроки снова могут входить на свободные места.

На macOS токен по умолчанию действует в рамках запущенного экземпляра, поэтому несколько окон можно тестировать на одном компьютере. Для проверки возврата после полного закрытия клиента запускай его с отдельным профилем, например `open -n "/путь/к/Coin Rush.app" --args -coinrush-profile player4`. При повторном запуске укажи тот же профиль и введи код комнаты. Для разных клиентов используй разные имена профилей.

## Результаты проверок

- **macOS.** Полный матч, лимит комнаты и возврат участника с сохранением счёта.
- **Android.** Отображение монет, одновременная работа стика и рывка, увеличенное меню подключения.
- **WebGL.** Матч с хостом на Mac и возврат с прежним счётом после обновления той же вкладки.
- **Unity EditMode.** Прошли 10 тестов NUnit на правила раунда и спорный подбор.

### Производительность на Android

На одном телефоне выполнены два 20-секундных замера вывода кадров через Android SurfaceFlinger. После отключения Bloom и HDR и обновления видимости монет только при изменении состояния средний интервал между кадрами снизился с **21,6 до 16,0 мс**. SurfaceFlinger показал **46,3 → 62,5 FPS**. Интервалы **32–33 мс** составляли около трети первого замера и исчезли в повторном прогоне.
